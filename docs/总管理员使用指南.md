# liaisonyy 总管理员使用指南

> 适用版本：0.3.2
> 总管理员只有一个，由服务端初始化时创建。

---

## 1. 部署服务端

### 1.1 放置文件

1. 在 **D 盘**建一个目录，例如 `D:\liaisonyy\`。
2. 把 `liaisonyy-server.exe` 放进去。
3. 双击运行。Windows 下**不会弹出控制台窗口**，服务端在后台静默运行。第一次启动会在同目录创建：
   - `data\liaisonyy.db`：数据库（密文 + 元数据）
   - `data\keyring.bin`：服务器主密钥（审计链、公开媒体加密）
   - `data\tls\`：自签 TLS 证书
   - `data\setup_token.txt`：初始化口令
   - `data\logs\server.log`：运行日志
   - `data\panic.txt` / `data\last_error.txt`：仅在异常时出现
4. 初始化口令在 `data\setup_token.txt`；启动后 API 为 `https://127.0.0.1:47820`，管理后台为 `https://127.0.0.1:47820/admin`。

> **不要把服务端放在 C 盘**：教室电脑 C 盘可能还原，数据库和密钥会丢。所有数据都在 `data\` 里，备份时整个目录一起拷。

可在 exe 同目录放 `config.toml` 自定义：

```toml
school_name = "杨村一中"
server_name = "杨村一中 liaisonyy"
port = 47820
data_dir = "data"
```

命令行 `--data-dir` / `--port` 优先；`school_name` / `server_name` 只在数据库尚未设置时写入。

### 1.2 防火墙

首次运行 Windows 会弹防火墙提示，请允许：

- TCP 47820（客户端 API / 管理后台）
- UDP 47821（服务发现）

如果没弹窗或误点了拒绝，用管理员权限执行：

```bash
netsh advfirewall firewall add rule name="liaisonyy" dir=in action=allow protocol=TCP localport=47820
```

### 1.3 开机自启（现实限制）

服务端**没有内置系统托盘**；C 盘还原会清掉启动项。可以用命令行把启动脚本放进当前用户的「启动」文件夹：

```bash
liaisonyy-server.exe --install-autostart
```

它会在 `%APPDATA%\Microsoft\Windows\Start Menu\Programs\Startup\liaisonyy-server.vbs` 写入启动脚本（VBS 隐藏窗口启动，不会弹出 cmd）；用 `--remove-autostart` 删除。由于启动文件夹在 C 盘，还原卡环境下仍可能失效，建议每天早上由值日生/管理员确认服务端已启动。

### 1.4 客户端部署

客户端由**各班班级管理员**统一部署（放 D 盘、配置服务器地址、创建桌面快捷方式、负责更新），学生只使用快捷方式登录/聊天。具体步骤见《班级管理员使用指南》1.1。文本输入使用系统输入法；PIN/密码页面的自带键盘保留，客户端不再内置中文键盘。

## 2. 初始化服务端（只做一次）

1. 在服务端那台电脑（或同一内网的电脑）运行 `liaisonyy.exe` 客户端；`liaisonyy.exe` 和 `WebView2Loader.dll` 要放在同一目录，系统需要 WebView2。
2. 欢迎页确认服务器地址是 `https://127.0.0.1:47820`（或服务器 IP），点「连接服务端」。
3. 看到「服务端尚未初始化」→ 点「初始化服务端」。
4. 填写：
   - **初始化口令**：`data\setup_token.txt` 里的 8 位数字
   - **总管理员 YY 号**：例如 `admin`（3–20 位字母数字下划线，不能纯数字）
   - **显示名称**：例如「总管理员」
   - **密码**：8 位以上，含字母和数字，建议 12 位以上
5. 点「初始化」。
6. 屏幕会显示一个 **恢复码**（16 位数字），只显示一次：
   - **立刻抄下来，离线保存**（不要存在服务器上）。
   - 忘记总管理员密码时，它是最后的恢复手段；丢失后所有管理员加密数据可能无法恢复。
7. 初始化完成后，用总管理员 YY 号 + 密码登录。

> 总管理员账号不绑定班级，不显示在班级账号列表里；用「uid/YY号登录」入口登录。

## 3. 创建班级与导入名单

在客户端登录总管理员 →「我」→「管理」：

### 3.1 创建班级

1. 填「名称」（例如 `高二(5)班`）和「年级」。
2. 点「创建」。
3. 客户端会自动生成该班的**班级托管密钥**并上传；服务端不保存明文密钥。
4. 创建成功后，该班自动拥有一个班级群。

### 3.2 导入名单

1. 在「导入名单」里选择班级。
2. 在文本框里每行写一个学生姓名（例如从 Excel 复制一列）。
3. 点「导入」。
4. 学生注册时就能在名单里选自己的名字。

> 名单的导入/编辑**只有总管理员**能做；班级管理员只能查看。重名学生建议在姓名后加学号后四位区分。

### 3.3 指定班级管理员

1. 先让学生注册账号（或你手动确认其 UID）。
2. 在「设班级管理员」里填班级 ID 和学生 UID，点「设置」。
3. 该学生角色变为班级管理员，并拿到本班托管密钥的包裹。
4. 班级管理员必须用密码登录。

## 4. 管理入口

### 4.1 客户端「管理」页（功能最全）

用总管理员账号登录客户端 →「我 → 管理」：

- **看板**：账号、在线、有效会话、24h 登录失败、今日/累计消息、数据库与媒体占用、待处理举报、禁言/封禁数、逐班统计。
- **举报处理**：忽略、隐藏消息、禁言、封禁；也可按 UID 手动禁言/解封/封禁。
- **转班审批**：总管理员可一次批准转出与转入两侧。
- **公告管理**：全校公告或指定班级公告。
- **审计日志**：按动作前缀筛选、校验 HMAC 哈希链、导出 CSV 到「文档」目录。
- **备份**：一键备份、列表、下次启动恢复。
- **发布客户端更新**：上传签名后的 exe。
- **聊天解密（内部工具）**：输入学生 UID → 选择会话 → 查看明文；每次读取密钥都会写入审计。仅用于处理举报/恢复数据，请遵守隐私边界。

### 4.2 网页管理后台

浏览器打开 `https://服务器IP:47820/admin`（自签证书会提示不安全，选择继续访问）。

- 用总管理员 YY 号 + 密码登录。
- 概览、班级、名单、审计等基础管理。
- 网页后台**不做解密、不展示任何聊天记录**；创建班级需要客户端生成托管密钥，请在客户端创建。
- 已加 CSP、`X-Frame-Options: DENY`、`nosniff` 等安全头。

## 5. 重置密钥

总管理员可以为**任意班级**的学生生成重置密钥：

1. 客户端「管理」页 →「生成重置密钥」。
2. 填学生 UID、有效期（分钟），点「生成」。
3. 把 8 位密钥线下告诉学生。
4. 学生用「忘记密码」完成重置。

班级管理员也可以为本班学生生成；总管理员是兜底。

## 6. 数据备份与恢复

### 6.1 管理后台一键备份

「管理 → 备份 → 立即备份」会：

1. 用 `VACUUM INTO` 生成一致性数据库快照；
2. 复制 `media/`、`keyring.bin`、`media.key`、`identity.txt`；
3. 存到 `data/backups/backup-<时间戳>/`。

列表会显示备份时间和大小。建议每周一次 + 大版本升级前一次。

### 6.2 恢复

1. 在管理后台点备份右侧「恢复」。
2. 系统只写一个 `restore_request.txt` 标记；**下次启动服务端时**才执行恢复。
3. 重启服务端后：当前数据库/媒体先移到 `data/pre-restore-<时间戳>/`，再复制备份内容。
4. 确认数据正常后，可手动删除 `pre-restore-*` 目录。

> 恢复不会热替换正在使用的数据库，避免损坏。`keyring.bin` 必须一起备份；只备份数据库会导致审计链和媒体无法解密。

### 6.3 手动备份

也可以停服后直接复制整个 `data\` 目录到 U 盘/另一块盘。

## 7. 升级与迁移

### 7.1 客户端自动更新

1. 不需要配置任何签名密钥。打 tag（如 `v0.3.4`）或 Actions → build → Run workflow（勾选 `publish_update`、填 `version` / `min_client`）。
2. 工作流会构建客户端和服务端，生成 `manifest.json`，并发布到 GitHub Releases。
3. 客户端**每次启动都会强制检查更新**：同时查询 GitHub Releases 和当前服务端，在能连上的源里选版本号最高的那个；有更新时必须更新成功才能进入，检查失败只能重试。
4. GitHub 下载会并发尝试直连和内置加速源；服务端源由服务端中转。下载后校验 SHA-256，再自替换重启。
5. 小窗不会自动弹出；点托盘图标才显示，随时可关闭。0.3.1 及更早客户端需要手动安装一次 0.3.2+。

**本地更新源（GitHub 不可达时）**：把 `manifest.json` 和 `package.exe` 放进服务端的 `data\update\`。管理后台「发布客户端更新」也会写这两个文件。清单里的 `version` 高于当前版本才会触发更新，`sha256` 必须与实际文件一致。

### 7.2 服务端升级

服务端已支持自动更新：

1. 服务端启动时同时检查 GitHub Releases 和本地 `data\update\manifest.json`，选版本号最高、且带 `server.windows` 的清单。
2. 发现新版本会下载对应安装包，校验 SHA-256，自替换并重启。
3. 本地服务端包约定放在 `data\update\server.exe`；本地清单里加 `server.windows`（`url` 可写相对路径）。
4. 服务端没有命令行/UI，更新状态写在程序同目录 `update-status.txt`（不可写时退回 `data\`）并注明来源，详细日志在 `data\logs\server.log`。
5. 更新失败不会阻止本次启动，下次启动会再试。

也可以手动升级：

1. 停服。
2. 管理后台先做一次备份（或手动复制 `data\`）。
3. 用新 `liaisonyy-server.exe` 替换旧 exe（不要动 `data\`）。
4. 启动，检查日志和网页后台。

### 7.3 迁到 Linux 云服务器

源码支持 Linux 构建；步骤大致：

1. 在 Linux 上编译/放置 `liaisonyy-server`。
2. 把 `data\` 整个目录拷过去。
3. 配置端口/证书（自签证书可继续用；客户端会记录指纹，换证书后需要管理员清除对应指纹）。
4. 客户端设置里把服务器地址改成云服务器地址。
5. 放行 TCP 47820 和 UDP 47821（发现用）；管理后台与 API 同端口，公网访问请用防火墙限制来源。

## 8. 安全建议

- **恢复码**离线保存（纸质/加密 U 盘），不要放在服务器电脑上。
- 总管理员密码使用强密码（12 位以上），不要与学生共用。
- 不要把 `data\keyring.bin`、`data\media.key` 发给任何人；备份文件也要妥善保管。
- **GitHub 仓库与 Release 权限**只掌握在可信管理员手里；自动更新信任 GitHub HTTPS 与清单里的 SHA-256，能改 Release 的人就能推送更新。
- 服务端 API 与管理后台同端口监听 `0.0.0.0:47820`；请用 Windows 防火墙只放行需要的网段，管理后台不要暴露到公网。
- 客户端首次连接会记录证书指纹；更换服务端证书后，需在客户端清除旧指纹（或让学生重新安装），否则会拒绝连接。
- 定期检查审计日志中的异常登录/管理操作，并用「校验哈希链」确认审计未被篡改。
- 教室电脑可能被同学接触；离开时锁屏，服务端进程不要随意交给学生操作。

## 9. 当前版本限制

- 服务端没有系统托盘；可用 `liaisonyy-server.exe --install-autostart` 写入启动文件夹实现开机自启。
- 客户端内置软键盘不含中文输入法；中文请用系统输入法。
- 私聊会话密钥在建立好友关系时生成，暂不支持管理员主动轮换；改密码会重新包裹密钥，班群成员变化会自动轮换班群密钥。
- 自动更新需要能访问 GitHub Releases 或至少一个内置加速源；客户端启动时全部不可达会停在「检查更新失败」，只能重试。0.3.1 及更早客户端需手动安装一次 0.3.2+。
- 首次 TLS 连接采用 TOFU，仍可能被抢先的中间人攻击；之后指纹变化会被拒绝。

核心流程（注册、登录、好友、私聊、班群、资料、举报、公告、转班、审计、备份、解密、更新）均已完成。

## 10. 常见问题

**Q：服务端启动后客户端连不上？**
A：确认服务端进程在运行；确认防火墙放行 TCP 47820；确认客户端地址是 `https://服务器IP:47820`；自签证书提示可以忽略（客户端已允许）。

**Q：初始化口令丢了？**
A：在 `data\setup_token.txt` 里；如果服务端已经初始化，该口令不再需要。

**Q：总管理员密码忘了？**
A：用初始化时抄下的恢复码恢复（当前客户端还没有恢复码界面，需后续版本或手动处理）；如果恢复码也丢了，管理员加密数据可能无法恢复。

**Q：数据库越来越大？**
A：服务端永久保存聊天记录（按需求不删）。文本消息很小；定期备份并关注磁盘剩余空间。

**Q：可以一个学校多个服务端吗？**
A：当前按「全校一个服务端」设计；多个服务端会导致客户端发现冲突（后续版本），请只保留一个。
